# 綜合分析：設備老化、參數食譜錯誤與真空溫度異常

- 目標：
    - 建立跨製程綜合分析能力：跳脫微影或蝕刻的單一製程框架，掌握設備老化、人為配方載入錯誤、以及腔體環境突變（真空/溫度）等跨模組、系統性異常的判讀邏輯。
    - 精通多維度數據指紋（Multi-CTQ）交叉比對：學會辨識當「多個獨立電性與幾何指標同時超規」時的物理意義，並能區分時間序列（Time-series）感測器突波與長期趨勢變異。
    - 實作 AI 閉環控制（Closed-loop Control）思維：將前四章所學的機器學習預測、無監督重建誤差、以及統計控制界限，真正轉化為產線端的「自動預警、自動熔斷、自動防禦」三大自動化 Pipeline 行動。

## 模式一：設備與硬體老化 (Equipment Aging)

-   1. 數據庫指紋與機台 Log 特徵
    - Cycle Time Log 趨勢：單片晶圓的生產週期時間（Cycle Time）隨時間拉長，或機台步進馬達的升溫日誌異常。
    - 良率與警報趨勢：在歷史資料庫中，該機台（Tool ID）所產生的晶圓缺陷率呈現逐日、逐周的系統性緩慢爬升。
    - 測試端指紋：頻寬測試整合中最常見的是探針床（Probe Card）接觸電阻（Contact Resistance）隨測試次數（Touchdown Count）增加而線性變大。
-   2. 底層物理機制
    - 機械與耗材耗損：機台軸承磨損、機械手臂定位精度產生奈米級漂移，或是測試探針（Probes）表面氧化、磨損，導致高頻電性量測時訊號嚴重失真，引發系統性的長尾偽缺陷（False Alarms）。
-   3. Python 系統自動化行動 (Action)
    - 預測性維護 (PdM)：透過 Pandas 的滾動平均（Rolling Mean）監控每日缺陷率 slope（斜率），當斜率連續 7 天為正時，系統自動將 alert_status 標記為 WARNING，並在報表中加入「強烈建議安排 PM（定期保養）更換探針卡」的提示。

## 模式二：食譜錯誤 (Recipe Error)

-   1. 數據庫指紋與機台 Log 特徵
    - 全片毀滅性失敗 (Near-Full / Full Fail)：晶圓點位圖（Wafer Map）呈現全片大面積、無差別的集體失敗，良率瞬間腰斬。
    - 多欄位交叉矛盾：在 NPI 測試資料庫中，多個獨立的關鍵品質特性（多個 CTQ，如頻寬、漏電流、電阻、膜厚）同時嚴重超出規範限制（Spec Limits）。
-   2. 底層物理機制
    - 人為超馳或配方載入錯誤：現場操作員在換批次（Lot Change）時，進行了手動超馳（Manual Override），或者自動化系統誤載入了不適用的製程參數食譜（Recipe）。例如：誤將 28nm 製程的曝光能量與參數，套用到 16nm 的晶圓批次上，導致製程視窗（Process Window）完全錯位。
-   3. Python 系統自動化行動 (Action)
    - 即時熔斷與攔截：當 YieldPredictionRecord 偵測到單片預測良率暴跌且多 CTQ 超規時，系統觸發 CRITICAL（嚴重警報），直接向產線自動化控制系統（MES/EAP）下發 HOLD_LOT 熔斷指令，強制暫停該批次後續的所有製程，阻止髒資料與不良品繼續流向後段封測。

## 模式三：真空與溫度異常 (Vacuum & Temp Abnormality)

-   1. 數據庫指紋與機台 Log 特徵
    - 時序感測器突波：製程機台（如 PVD、CVD 或蝕刻腔體）的 Chamber_Pressure_Log 或熱電偶 Thermocouple_Temp_Log 在特定時間戳記（Timestamp）出現瞬間爆裂式的突波或驟降。
    - 複合型物理指標超規：測試端呈現 Thickness Deviation（膜厚）與 OVERLAY_X/Y（疊加偏移）同時出現嚴重異常。
-   2. 底層物理機制
    - 熱脹冷縮與物理應力破壞：當腔室發生局部漏氣導致真空度不穩，或是加熱盤（Heater）溫度控制失效時，晶圓會在極短時間內承受劇烈的熱衝擊（Thermal Shock）。這會造成晶圓各層薄膜之間的熱膨脹係數（CTE）嚴重失配，引發嚴重的物理幾何形變（重邊缺陷、晶圓大面積翹曲），甚至導致內部晶格缺陷與電路脆裂。
-   3. Python 系統自動化行動 (Action)
    - 無監督異常防禦：此類複合型異常極難用傳統規則（Rules）定義。系統會調用無監督的 ConvAutoEncoder 模型。當這批晶圓的影像輸入後，由於其重構圖形極度扭曲，模型會噴出超高的重建誤差（Reconstruction Error）。系統偵測到重建分數超標後，會自動聯結時序資料庫，抓出對應時間點的溫度/壓力突波，完成自動化根因追溯。

- 總結：在第六章的領域知識（Domain Knowledge）中，我建立了完整的缺陷判讀筆記。我不僅精通微影（6.1、6.2）與蝕刻（6.3）的單一製程失效，更在 6.4 中建構了跨模組的綜合分析思維。當面對設備老化引發的接觸電阻爬升時，我用 Python 實作 預測性維護；面對配方錯誤引發的多 CTQ 同時超規，我設計了 自動化熔斷機制；而面對最棘手的真空與溫度異常，我則透過 AutoEncoder 的重建誤差 進行無監督防禦。這種將大數據管道、AI 模型與半導體實體製程物理機制完美閉環的系統整合能力，是我最核心的差異化亮點。
